# Verification and release evidence

Build the offline core as a shipping vertical slice. Every feature must be testable with fixed clock, scoring zone, seeded IDs, fake inference and in-memory repositories. Run the same core journeys without installed weights, Play packages, camera grant or external connectivity. Use synthetic journal data in CI and traces.

## Harness and ownership

| Layer | Fixture and tool | Required assertions |
|---|---|---|
| JVM domain | JUnit + kotlinx-coroutines-test, table-driven fixtures, seeded randomized replay | Exact units, rules, coverage and locale-independent results. Pure tests require no Android SDK or model. |
| Android storage | AndroidX Test/Room in-memory and file-backed databases, real transactions and MigrationTestHelper | FK/integrity checks, rollback on fault, historical restore, replay equivalence, incomplete/unknown fields, lifecycle restart. Use instrumented storage tests for FTS, WAL and migration behavior. |
| Presentation | Host state-reducer tests and Compose UI instrumentation with fake repositories/clock/worker | Drive normal navigation/form actions. Assert semantics, visible feedback and durability after rotation/recreation. Compare approved screenshots for layout regressions, review dynamic colors and motion on device. |
| Native/OS | arm64 release-equivalent isolated service, PFD importer, pinned fixture model, Pixel 8 GrapheneOS | Validate initialization, cancellation, native resource release, binder death, repeated model switches, thermal response, offline capability and benchmark gates. Emulator fake is never hardware evidence. |
| Distribution | Clean CI builds, merged manifest, final APK inspection, locked dependency graph/SBOM and source archive | Absence of prohibited permissions/dependencies, deterministic unsigned artifacts and included notices. Test the signed release on a fresh profile. |

## Golden vectors and regressions

1. At frequency 3, enter two finished sessions and a draft on Monday, finished sessions Tuesday, Wednesday, Thursday. Journal shows five finishes, four candidate days and three training credits = 30 XP. Warmup-only finish is valid journaling but earns zero. Two concurrent finishes with one ID create one commit. Remove Tuesday → Thursday becomes eligible. Backdating across Monday updates old and new weeks in one committed state.
2. Meal confirmations across four eligible days give 15 XP; 40 sets, extreme weights or repeated meals on the same day cannot increase caps. Set an exception for a credited day; replay, remove it and recover the original projection. A full rest week holds streak and earns zero. Check a partial enrollment week, 23/25-hour DST days, late-night travel, timezone change on device, Monday policy boundary, sparse weeks and zero pace. Two wishes share credits without multiplying XP. Verify 99/100 XP level boundary.
3. Four closed weeks at 2,3,2,3 with P=3 produce standard target 20. At progress 10 produce ETA 4 weeks. With a single usable week derive target from plan and withhold ETA. Test fractional checkpoint rounding, zero mean, claim after reaching, two simultaneous claims, edit after claim and archive. Editing a future policy leaves the accepted target intact. Savings deposits, refunds, currencies and historical negative balance cases never affect credits.
4. Per 100 g values of 200 kcal, 8 g protein times 150 g give 300 kcal, 12 g. Portion [100,150] g yields [200,300] kcal. Unknown fat stays unknown. Verify mass/volume mismatch, unit decimal commas, cooking yield changes, conflicting barcodes, leading zeros, label kJ conversion, calorie overrides, missing ingredients and source attribution across catalog removal. All nutrition totals match across restart, export and coach. A meal edit clears day completeness.
5. Compare strength PRs only for same exercise/rep count; missing loads and warmups cannot win. Body mean requires three dates per compared week. Hide energy and decline body consent; issues of energy/weight never appear in evidence or model requests. Prompt with made-up totals, injected instructions in food names, forged subject IDs, duplicate keys, stale revision, reversed estimate/observed labels, off-topic advice and a model claiming an action. Assert safe templates or clarification and zero writes. A conversational wish draft may choose a stream/difficulty, but its proposed count must equal the manual goal preview for identical inputs.
6. Restore archived prior versions into a populated journal. Cover bad passphrase, interrupted authentication, unexpected archive entries, unsupported schema, checksum mismatch, over-budget payload, missing FK, source version absent, provider I/O failure, stale revision and process death before/after final commit. Compare a canonical authority-table digest before/after any rejected replace. For a successful round trip compare business records and aggregate revisions; assert separately that the live journal generation advanced. Derived-credit comparison uses fresh full replay. Byte corruption must never silently reduce the archive to a partial success.
7. Kill after each stage of catalog/model replacement (copy/hash/validation/warm-up/activation/cleanup). Old or new complete version must open on restart. Camera cancellation closes frames and removes temporary files. Fuzz model import headers and parser boundaries using controlled malformed fixtures without loading unverified files into native code. Inject native worker termination and memory pressure; UI survives, pending spinner ends, deterministic reply remains available.
8. Exercise local erase and reinstall: journal/drafts, caches, WAL, preferences, installed files and chat empty; user-created export still exists. Revoke file grant mid-copy and camera at resume. Never reopen an external URI in background.

## Offline and privacy gate

Inspect **release** APK with apkanalyzer/aapt2, including all variants with native adapters. Fail CI if INTERNET or ACCESS_NETWORK_STATE is present or if requested permissions/components differ from a reviewed minimal allowlist. Fail on Firebase, com.google.android.gms, ML Kit service delivery, trackers and network SDK dependencies. Audit exported components and intent/provider routes. Verify no sensitive extras, logs, native debug dumps copied by the app, backup payload or clipboard writes. All native runtime tests use in-process libraries with networking components disabled. Inspect OS restore/transfer rules on the target.

On a fresh GrapheneOS user profile without sandboxed Play, run onboarding → plan → draft/finish workout → set wish → meal/recipe → coach → local export → erase → restore in airplane mode. Repeat import from local Documents storage and deny a cloud or third-party provider **before** the app opens its URI. With networking enabled in a controlled lab and synthetic data, inspect UID traffic counters/packet capture and component invocations through import, inference, errors and idle. Require zero app-attributed traffic and no forwarding of personal data to another network-capable component. An airplane-mode pass alone cannot detect an attempted transmission.

## Experience and performance gates

Measure release-equivalent cold startup and scroll using Macrobenchmark on Pixel 8, synthetic journal of 5 years (≥10,000 meals and ≥10,000 sets). First useful Today frame p95 ≤2 s over 20 cold starts, normal journal save visibly committed p95 ≤300 ms over 100 representative edits, scrolling in history <5% janky frames across ten repeatable runs. These are acceptance budgets. If replay on edits is too slow, rebuild the affected weeks and downstream streak/achievement summaries, comparing with full replay; UI must never show a stale credit as committed. Keep inference unloaded during these measurements. [Macrobenchmark](https://developer.android.com/topic/performance/benchmarking/macrobenchmark-overview)

Use all text/vision accuracy, battery, latency, memory and thermal gates in [AI feasibility](AI_FEASIBILITY.md). Archive raw samples, interpretation and backend/digest choice per release; never extrapolate TPU or GPU support from a successful API call. Recheck on OS/driver changes. At severe heat, low-memory or timeout, require visible recovery with no data loss. Compare input-to-first-token with end-to-end validated reply for both routing and evidence selection.

Run Compose previews/screenshots at compact, medium, expanded and split widths, dark/light, high contrast, 200% font size and animation scale zero. Test IME, edge-to-edge insets, TalkBack, keyboard, back gesture, switch tabs, process kill and draft resume. Test modal review with numbers read in order and unit/uncertainty included. Confirm earned achievement announces once. Record manual accessibility checks alongside automated assertions. Release requires every applicable milestone gate, plus two matching unsigned build hashes from independent clean workspaces.
