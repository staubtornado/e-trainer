# Material 3 Expressive interaction design

## Today on a Pixel 8

Use an edge-to-edge vertical reading order. Start with the selected date and a reachable settings button. Follow with a wide wish card: the user’s own short title, a large count such as **10 of 20 training days**, and four segmented checkpoints. Tapping the card opens the rule/evidence sheet. When no wish is pinned, feature the current workout draft, otherwise the next log action. A rest day leads with its recovery label. Never show an empty ring as the primary message.

Below the hero put **Resume workout / Log workout** and **Log meal** in the thumb-accessible area. Then show a weekly strip of training, rest and exception days with a spoken summary; logged nutrition and optional targets with coverage; the latest achievement and one coach insight with “Based on…” evidence. Hide disabled features. Keep units and the date attached to the value. A date selector can inspect history; inputs opened from it default to that date.

## Destinations and screen states

Use five labeled top-level destinations: Today, Train, Eat, Wishes and Coach. Settings is available from the top app bar. Use a Material navigation bar on compact windows (<600 dp), rail at 600–839 dp and rail plus list/detail when width ≥840 dp and both panes fit at current font scale. Respect separating hinges. Window metrics, not device name or orientation, decide. Preserve independent tab stacks, draft IDs and scroll anchor on resize, rotation and process recreation. Back closes a sheet, then a detail, then the current stack; at a non-Today tab root select Today; at Today root use platform exit. Keyboard/IME Back dismisses editing before navigation.

## Tokens and components

Use MaterialTheme colorScheme with Android 12+ dynamicLightColorScheme/dynamicDarkColorScheme and system/light/dark selection. Provide an app-owned fallback palette seeded with deep teal (#006B62) and warm terracotta as a tertiary accent. Resolve on-colors/tonal containers per scheme; never use a wallpaper color directly behind text. Theme assets are local. Use bundled open-licensed **Barlow** for headings/numerals after OFL notice review and platform Roboto for body text; use platform sans if a font is missing. Never use a downloadable font provider. Type scale: hero/headline 36/44 sp, section 22/28, body 16/24, labels 14/20. Allow wrapping and system font scaling. Reserve tabular numerals for rapidly changing timers; keep text descriptions stable.

Use an asymmetrically rounded hero (32/32/12/32 dp), related log cards (20 dp), shape grouping for contiguous sets, and pill-shaped primary actions. Space on a 4 dp grid: 16 dp compact side gutters, 24 dp between sections, 8 dp between related controls. Visual density follows task: dense comparable set rows during logging, a spacious milestone view on return. Cards have one clear primary action with distinct accessible secondary actions. Use Material progress indicators, primary/tonal buttons, chips for evidence and real text labels. Keep training vs nutrition vs recovery distinguishable by icon and label as well as color.

Prefer stable expressive APIs in the pinned Material release. Wrap expressive progress, button groups and shape transitions in local design-system composables. If a desired component requires unstable opt-in, use stable Surface, Button, LinearProgressIndicator and shape/size animation with the same semantics. Stable NavigationBar/Rail and width breakpoints suffice if an adaptive convenience component is experimental. [Material 3 in Compose](https://developer.android.com/develop/ui/compose/designsystems/material3) · [Material component release status](https://developer.android.com/jetpack/androidx/releases/compose-material3)

## Motion and accessibility acceptance

- Animate progress from previous committed value to the new one over 250 ms. Briefly expand a checkpoint or reveal its label when crossed. Claim uses a single 450 ms shape transition and optional user-enabled haptic. Never restart celebrations on recomposition, tab return or replay. Edits that remove a credit simply update the count.
- Use system animator-duration scale and a Settings “Reduce motion” override. Either disabled animations or override gives immediate final states, static success icon and announcement. No looping decorations, flashing or essential timed messages. Pause animations in background.
- Minimum interactive target 48 × 48 dp, including set controls and chart points selected via list. Meet 4.5:1 contrast for normal text, 3:1 large text and essential graphics in both fixed and representative dynamic schemes. Do not encode success, rest or uncertainty by color alone. Decorative icons have no duplicate description; merge progress semantics into a single announcement with value, target and unit. [Compose accessibility defaults](https://developer.android.com/develop/ui/compose/accessibility/api-defaults)
- Test TalkBack order, accessibility actions for reorder/undo, D-pad/keyboard traversal, Switch Access, visible focus, German long strings, RTL and 200% font size. Never truncate amounts or cover Save with the IME. If panes stop fitting, stack. Apply Scaffold content insets once; account for system bars, cutouts and IME in the editor. Use enableEdgeToEdge and appropriately contrasting system bar icons.
- Render loading, empty, partial, error, disabled and populated previews per primary surface. In low-memory state replace busy inference with an actionable response. Manual-entry and rest flows must remain finishable with touch, keyboard or TalkBack.
