# Android architecture

## Build and dependency boundaries

Start a native, single-activity Kotlin app, package `org.etrainer.app`, minSdk 31 (deliberate Pixel-first scope), compileSdk/targetSdk 37. Produce an arm64-v8a release APK and an emulator build for core flows with a fake inference adapter. Use a pinned stable Android Gradle Plugin, its supported Gradle wrapper/JDK and matching Kotlin Compose compiler. Pin Material 3 1.5.0 and Navigation 3 runtime/UI 1.2.2 as the research baseline. Resolve and lock a single compatible stable set at M0. Do not copy dynamic dependency selectors from samples. [Android 17 SDK](https://developer.android.com/about/versions/17/setup-sdk) · [Material release table](https://developer.android.com/jetpack/androidx/releases/compose-material3) · [Navigation 3 releases](https://developer.android.com/jetpack/androidx/releases/navigation3)

| Gradle project | Owns | Allowed project dependencies |
|---|---|---|
| :domain (Kotlin/JVM) | Typed records, quantities, pure rules, calculations, coach context types, repository and inference ports. Inject Clock and ZoneId. | None |
| :data (Android library) | Room entities, DAOs and migrations, DataStore, catalog readers, import/export, repository implementations, replay transactions. | :domain |
| :inference (Android library) | Model handles, text/vision/OCR adapters and private bound worker service; no exported app API. | :domain |
| :app | Composition root, feature packages today/train/eat/wishes/coach/settings, ViewModels, CameraX, SAF, Compose theme/navigation. | :domain, :data, :inference |

Use constructor injection and a small application-owned container. Bind interfaces in one place, pass factories via ViewModel creation extras; replace container in tests. This avoids code generation beyond Room and gives an auditable list of capabilities. Repositories expose immutable domain projections rather than Room entities. Put feature-specific state in its feature package, share primitives only where two features need them. No network client, remote repository or synchronization layer. [Android architecture guidance](https://developer.android.com/topic/architecture)

~~~mermaid
flowchart LR
  UI[Compose screen] --> VM[Feature ViewModel]
  VM --> UC[Domain query or command]
  UC --> Repo[Local repository port]
  Repo --> DB[(Room journal)]
  Repo --> Cat[(Versioned catalogs)]
  VM --> Coach[Coach coordinator]
  Coach --> Facts[Read-only fact service]
  Facts --> Repo
  Coach --> Worker[Bound inference worker]
  Worker --> Reply[Typed selection]
  Reply --> Validate[Validator and template renderer]
  Validate --> UI
~~~

Only the composition root wires these components. The edge from a port to storage denotes an implementation. Do not initialize the main app container in the service process. The inference process receives bounded requests and read-only file descriptors, with no repository capability. Run native processing in a nonexported isolated bound service. Use typed Binder messages for small tensors/metadata or private read-only PFDs for large blobs. Map verified model descriptors read-only; if a loader requires a path, qualify a descriptor-backed path and lifetime in the PoC. Never grant the isolated UID access to the DB directory. Keep UI and templates working if isolated loading fails. Use death recipients to complete pending calls and clear stale handles. No localhost server.

## State, navigation and concurrent work

Use typed Nav3 keys with stable IDs and one saved back stack per top-level destination. Screen ViewModels expose StateFlow<UiState>, collect with collectAsStateWithLifecycle. Compose emits actions; success follows observed committed state. Persist journal drafts in Room on field/set confirmation, restore edit buffer and selection across rotation; SavedStateHandle holds IDs, tab and scroll position only. Drop transient sensitive input on process death. Collect structured errors at screen level. Use coroutines on IO for files/DB and a bounded single-owner worker dispatcher for native operations. Run one snapshot export on a read-only transaction; copy rows into bounded journal-owned staging and close the snapshot before compression or picker interaction. Never hold a Room transaction over inference, camera capture, picker UI or model copy.

Session finish, meal save, claim and policy change are idempotent commands using stable IDs and expected row revisions. Serialize journal writes through Room transactions. In that transaction invalidate/rebuild affected projections and increment journal revision. Observe flows after commit; use consistent read transactions for a coach turn or export. UTC instants for ordering and persisted civil dates for grouping. A foreground clock tick across midnight/week boundaries refreshes projections even without a write. Rest timer stores a deadline; recompute on resume, tolerate reboot/clock correction, offer dismiss. No exact alarm or background timer service.

Use Kotlin serialization with strict versioned DTOs at import and inference boundaries. DataStore holds device presentation options only. Use Room for any setting that changes an aggregate. Run imports/exports as explicit foreground actions with progress, cancellation and durable staging. Defer maintenance to next launch if interrupted. WorkManager was evaluated; the v1 workflows have no unattended work requirement. Avoid enqueuing inference, camera work or recurring polling. Add a unique local maintenance worker only through a later decision with manifest review.

## Model and catalog installation

Ship model metadata as a versioned APK allowlist (digest, format, exact length, tensor/tokenizer contract, runtime ABI, resource ceilings, source, license). Import a raw, uncompressed known model file through local ACTION_OPEN_DOCUMENT. Verify length while streaming, SHA-256, free space with reserve and format/header metadata before calling native code. Reject unknown revisions even if a sidecar claims a match. Store by digest in private no-backup storage. Warm with a synthetic input before marking usable. Switch the active digest transactionally only on success; keep previous until old descriptors close. Remove stale temp files on launch. App updates can extend the allowlist. Show file size, license and source before activation.

Catalog updates use a local pack of strict, length-bounded manifest plus UTF-8 NDJSON records (first line header, then one record per line). Ship approved regional pack hashes in the same release index. Build fresh private catalog tables from data, never execute SQL from a pack or open an imported SQLite DB. Verify declared version, rows, attribution, units, unique keys and completeness thresholds in [data model](DATA_MODEL.md). Build indexes and run integrity checks before atomic selection of the immutable version. Keep previous until readers close. Seed bundled USDA data on first use from a pinned asset with provenance. No full-world dump on the phone.

## Data protection and permissions

- Keep journal, catalog, settings and staging in credential-encrypted internal application storage. Android’s sandbox and file-based encryption protect data on a locked, correctly configured device; the DB is readable to the unlocked app. Exclude device-protected storage. No custom database encryption key in the APK. Close inference and clear prompts on background. Use FLAG_SECURE on personal screens including recents and suppress personalized IME learning where supported. The keyboard, accessibility tools, OS and user-chosen external copies remain trust boundaries. [Android file-based encryption](https://source.android.com/docs/security/features/encryption/file-based)
- Production manifest excludes INTERNET, network state, location, activity recognition, sensors, contacts, microphone, broad storage and media permissions. Only runtime request is CAMERA at scan/capture; declare hardware optional. Check each use, show rationale after denial, offer typing/import immediately. Only launcher Activity exported by app design. Inspect merged library components; allow only documented platform-facing entries. No telemetry, Firebase, Google Play Services, WebViews, external AI intents, analytics, crash upload, clipboard auto-copy or implicit sharing. Logs contain operation/error codes only.
- Allow local files through the system document picker with CATEGORY_OPENABLE and EXTRA_LOCAL_ONLY. Validate returned content URI **before opening a stream** against the OS system external-storage documents provider and a mounted local volume. Fail closed on unknown authorities; a picker hint alone cannot enforce locality. For exports use ACTION_CREATE_DOCUMENT with generic filename and show destination/unencrypted status. Never attach personal fields to picker intents. Release grants after copying. [Storage Access Framework](https://developer.android.com/training/data-storage/shared/documents-files)
- CameraX binds Preview/ImageCapture or ImageAnalysis to the visible lifecycle; keep only latest scan frame and close every ImageProxy in finally. Rotate/downsample with pixel and byte limits before inference; reject animations or undecodable images. Strip metadata by re-encoding orientation-normalized pixels to private cache. Use app-private temporary file for capture. Remove on confirm/cancel, background interruption or launch cleanup. V1 keeps no photo in a saved meal. Imported originals on the user’s volume are user-owned.
- Disable android:allowBackup; exclude all applicable data domains in legacy backup and API 31+ cloud **and** device-transfer rules; verify behavior on GrapheneOS. Native crash diagnostics remain OS-local. In integration builds use synthetic data for traces. [Android backup and transfer behavior](https://developer.android.com/identity/data/autobackup)

## Portable archive and recovery contract

Settings → Back up defaults to encrypted. Plain portable export requires a separate explicit choice and disclosure that the file contains personal records. Both use the same logical archive: versioned manifest plus one UTF-8 NDJSON file per authoritative journal table in a ZIP. Include units, coverage, stable IDs, revisions, policies, snapshots, rule versions, source identifiers/licenses, record counts and per-entry SHA-256. Exclude derived tables, models, catalog bulk rows, photos, UI-only options, chat, secrets and staging. Emit from a single consistent snapshot. Archive schema is independently versioned. Catalog absence after restore cannot change historical meals.

Encrypted envelope v1 uses maintained libsodium built from pinned source. Header has magic ETBK, version byte 1, fresh 16-byte salt, secretstream header. Derive 32 bytes with Argon2id v1.3, opslimit 3, memlimit 64 MiB, UTF-8 passphrase exactly as entered. Fixed parameters by version. Encrypt ZIP bytes in 64 KiB chunks with secretstream XChaCha20-Poly1305, the complete fixed envelope header as associated data on every chunk. Prefix ciphertext chunks with unsigned 32-bit big-endian lengths, maximum 65536 + ABYTES. Emit a distinct empty final authenticated chunk; reject missing final tag, extra bytes, wrong passphrase or changed order. No recovery key. Confirm passphrase on export. Stream only authenticated data to private staging. Wipe passphrase/key buffers where possible. Include cross-version reference fixtures and KDF resource tests. [libsodium password hashing](https://libsodium.gitbook.io/doc/password_hashing/default_phf) · [authenticated streams](https://libsodium.gitbook.io/doc/secret-key_cryptography/secretstream)

Stage and verify the complete backup privately before writing to the chosen URI. Provider failure may leave a partial document; report failure, attempt removal of this newly created file and never represent it as a backup. Restore validates format, hashes, required entries, parent references, numeric bounds, licenses, rule versions and total sizes before presenting counts and a **replace all journal records** confirmation. For the archive, order rows by primary key, reject duplicate JSON keys, and require the manifest to enumerate precisely the allowed entries with counts and checksums. Reject path traversal, duplicate entries/IDs, unknown newer schema, oversized lines (>64 KiB), >2 GiB expanded total or >10 million records. Stream using fixed names; never extract arbitrary paths. Convert old DTOs in staging. Treat journalRevision as a local monotonically increasing generation. Recheck it before commit, then advance from the live generation even when the imported archive contains a lower revision. Invalidate all pre-restore editor sessions and pending inference handles. Use one Room transaction to replace authoritative rows and rebuild projections; rollback leaves current journal usable. Local catalog/model activations are installation state and survive journal restore. Clear stale chats/drafts in memory. On full erase, close workers, release grants, cancel jobs and invoke Android clear-application-user-data after confirmation; this includes files, DB/WAL, preferences, installed packs and caches. Explain that external archives need separate deletion. Never promise physical erasure from flash.

## Reproducible release

Commit Gradle wrapper and distribution checksum, version catalog, locks, verification metadata, Room schema JSON, NDK/CMake versions, native commit and flags. Pin CI image by digest, SDK/build-tools/JDK and dependency repositories. Disable date, host paths and Git dirty-state stamps in outputs. Pin input dataset and notices; sort rows/entries, fix generated timestamps and locale. Build twice in independent clean directories from the same revision with identical inputs and compare SHA-256 of unsigned release APKs including native .so files. Sign the verified artifact separately; publish hash, SBOM, license notices, corresponding source and build recipe with release. Network access on a development machine to populate a verified build cache is separate from permissions in the installed app. Exercise Gradle offline against that cache. [Gradle dependency verification](https://docs.gradle.org/current/userguide/dependency_verification.html)
