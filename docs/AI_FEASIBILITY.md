# Offline inference decision for Pixel 8

Research cut-off 2026-11-23. The target is the **base Pixel 8, Tensor G3, 8 GB**, with a current GrapheneOS user build and no Google packages installed. Google documents the hardware. The runtime and model cards below establish upstream capabilities. This blueprint contains **no measurements on the target phone**. Support means passing the end-to-end gates below with a specific binary, model digest and OS build. [Pixel hardware specifications](https://support.google.com/pixelphone/answer/7158570)

## Runtime and model evidence

| Option | What the publisher establishes | Decision and remaining uncertainty |
|---|---|---|
| Gemini Nano / AICore | ML Kit GenAI uses the AICore system service, with API-specific device lists and model provisioning. The public list checked omits Pixel 8. GrapheneOS documents Google Play as an optional set of sandboxed apps. | Exclude AICore, ML Kit GenAI and Play provisioning. Stock Pixel features do not establish a supported public Prompt API on this OS. Installing optional Play is outside the supported setup. [ML Kit device lists](https://developers.google.com/ml-kit/genai) · [GrapheneOS usage guide](https://grapheneos.org/usage#sandboxed-google-play) |
| llama.cpp on Android | Maintained MIT runtime with an NDK/Android example, GGUF loading, CPU kernels and grammar-constrained decoding. The Qwen publisher supplies a Q4_K_M file for Qwen2.5-0.5B-Instruct (listed as 491 MB, Apache-2.0). | **Primary text PoC**. Build a pinned source revision for arm64-v8a, link in process behind JNI in a separate app process. CPU, one conversation, no HTTP server. Small install and bounded output fit an intent/evidence selection task. German/English accuracy, native compatibility and speed are open tests. [Android example](https://github.com/ggml-org/llama.cpp/blob/master/docs/android.md) · [runtime](https://github.com/ggml-org/llama.cpp) · [publisher files](https://huggingface.co/Qwen/Qwen2.5-0.5B-Instruct-GGUF/tree/main) |
| Larger Qwen | Publisher also supplies 1.5B quantized GGUF weights. | Compare Q4_K_M only if the small model misses quality gates. Same adapter, larger mapping, scratch and likely longer prefill. Qualify independently. Do not select by parameter count alone. [1.5B files and license](https://huggingface.co/Qwen/Qwen2.5-1.5B-Instruct-GGUF/tree/main) |
| LiteRT-LM | Google documents the standalone Android Kotlin engine, CPU/GPU backend selection, native GPU library declarations and a Gemma 3 1B IT example. A published 4-bit .litertlm file is roughly 0.6 GB. | **Engineering fallback** if the primary native stack fails qualification. Try standalone CPU with the exact matching file, warm and close engine/conversation off main; no model downloads. GGUF and .litertlm require different loaders. Gemma 3 1B is text-only. Compare under identical input limits before adopting a replacement; ship one text runtime. [Android guide](https://ai.google.dev/edge/litert-lm/android) · [files](https://huggingface.co/litert-community/Gemma3-1B-IT/tree/main) · [model card](https://huggingface.co/google/gemma-3-1b-it) |
| Standalone LiteRT | CompiledModel supports CPU and optional accelerators for compatible .tflite graphs. GPU library, operator coverage and driver matter. Google Tensor SDK’s documented chipsets include G5 and G6. | **Primary vision backend**, bundled standalone runtime on CPU. Do not use Play Services LiteRT. No G3 TPU path established, no NNAPI requirement. Probe GPU in engineering builds only, warm up on its owning thread, record actual delegated ops and CPU fallback. Keep CPU when unsupported or slower. [LiteRT Android](https://ai.google.dev/edge/litert/android) · [Tensor SDK release matrix](https://developers.google.com/edge/tensor-sdk/release-notes) |
| Multimodal generative inference | Gemma 3n E2B accepts images. Its effective parameter count depends on memory-saving techniques; host weights, vision encoder, caches and scratch still take space. | Research-only option for proposing food names from a single downsampled image. Requires a supported vision encoder/projector, prompt format, compatible packaging, license and measured headroom. Never infer edible mass, calories or allergens from captions. If it fails, the dedicated classifier path suffices. [Google model card](https://huggingface.co/google/gemma-3n-E2B) |

Gemma weights have custom terms, use restrictions and downstream notice obligations. A runtime’s open-source license does not grant rights to its weights, tokenizer, label maps or training images. Allow reviewed, hash-pinned user imports; distribute the GPL app without LLM weights. Record model owner, source revision, complete license/notice and format alongside each allowed digest. Review before offering any converted pack. Users can operate the production app without accepting model-host terms or creating an account. [Gemma terms](https://ai.google.dev/gemma/terms) · [Qwen publisher card](https://huggingface.co/Qwen/Qwen2.5-0.5B-Instruct-GGUF)

## Food recognition and lookup

| Candidate | Works offline by design | Product limit |
|---|---|---|
| Google AIY Food V1 dish classifier, TFLite variant | Try the published classifier and its matching label map with standalone LiteRT CPU. Verify exact tensor shape, quantization, orientation, normalization and IDs against a known input/output before enabling. Check variant-specific terms; publisher lists Apache-2.0 for Food V1. | One dish/crop returns ranked names. Full-plate softmax cannot enumerate all components. User adds crops/items or searches. Gate curated locale aliases against the installed catalog. [publisher model](https://www.kaggle.com/models/google/aiy/tfLite/vision-classifier-food-v1/1) · [model description](https://www.kaggle.com/models/google/aiy/tensorFlow1/vision-classifier-food-v1/1) |
| EfficientDet-Lite0, quantized COCO detector | Reference mobile detector can produce multiple boxes and class scores. Try common recognizable items such as bananas, then route each crop to the classifier. | COCO coverage is narrow for prepared dishes. Require evidence of better component recall and latency than manual crops before shipping. Food-101 is a closed-set dish dataset; its labels do not convey amounts or image redistribution rights. [detector guide](https://ai.google.dev/edge/mediapipe/solutions/vision/object_detector) · [Food-101 dataset](https://data.vision.ee.ethz.ch/cvl/datasets_extra/food-101/) |
| ZXing core + CameraX | Decode a cropped luminance plane on-device; support EAN-13, EAN-8 and UPC-A with check digit; accept typed codes. | Decoder yields an identifier. Only a matching local catalog or a user label supplies nutrients. [ZXing formats and license](https://github.com/zxing/zxing) |
| Tesseract4Android + tessdata_fast | Bundled native OCR and pinned English/German language data run locally. Verify transitive native licenses and language-data notices. | Optional, user-triggered label OCR after cropping. Parse decimal comma, kJ vs kcal, per serving vs per 100 g/ml and units. Show original crop alongside editable fields. Unresolved basis blocks calculation. [Android wrapper](https://github.com/adaptech-cz/Tesseract4Android) · [language data](https://github.com/tesseract-ocr/tessdata_fast) |

A single RGB image lacks scale, recipe composition and information about concealed oil or ingredients. Nutrition5k used measured component weights and specialized capture equipment including depth. V1 portion assistance uses labeled serving masses or user-entered household measures with food-specific conversions. Ask the user for grams or a range when evidence is weak. Keep name, portion and nutrient uncertainties separate. [Nutrition5k collection protocol](https://github.com/google-research-datasets/Nutrition5k)

**Base catalog.** Bundle a reproducibly generated, dated subset of USDA Foundation/SR Legacy common foods with stable FDC IDs, source nutrient units and selected aliases. FDC identifies its data as CC0. Preserve food preparation state and explicit energy source. Label provenance in search and meal detail. [FDC licenses](https://fdc.nal.usda.gov/) · [downloadable releases](https://fdc.nal.usda.gov/download-datasets/)

**Regional packaged foods.** Produce optional compact region/language packs offline from dated Open Food Facts bulk dumps. Retain barcodes as strings, normalize labeled basis, reject ambiguous units and keep incomplete fields nullable. A derived catalog must carry attribution, database license and corresponding share-alike distribution/access to the derivative and conversion information when publicly distributed. Individual contents have DbCL terms; images have separate CC BY-SA and possible third-party rights. Exclude images. Ship each OFF catalog separately from the USDA catalog and private journal, show credits on results and preserve provenance in exports. Review downstream distribution obligations per pack; physical separation alone does not resolve licensing. [OFF bulk data](https://world.openfoodfacts.org/data) · [OFF license guidance](https://openfoodfacts.github.io/documentation/docs/Product-Opener/api/tutorials/license-be-on-the-legal-side/)

## Qualification protocol and stop conditions

1. Build an arm64 release-equivalent harness with the same hardened OS settings, packaged native libraries, JNI lifecycle and importer intended for production. Record device/build fingerprint, ABI, OS hardening settings, runtime commit/flags, model digest/bytes, free storage, available RAM, CPU threads, tokenizer/context limits, battery level, ambient conditions and test inputs. Keep the phone unplugged for energy runs; fixed brightness, airplane mode, cool to baseline. Never require a weaker system security setting.
2. Compare CPU at two and four inference threads. Limit text to 1,024 total tokens including prompt, grammar and up to 96 generated tokens. Compute weight-only lower estimate as parameters × bits/8, then measure actual mapped pages, tokenizer, KV cache, activations, allocator and UI/service combined PSS. File size and system RAM are poor estimates of free working memory. Measure startup to usable UI separately from model open, prefill, time to first token, decode tokens/s and time to validated reply. No model mapped at app launch.
3. Run 10 cold process starts and 30 warm turns per candidate, report median, p95 and max with sample counts. Distinguish cold process from cold filesystem cache. Stress 15 minutes of repeated tasks and compare equal-duration idle-screen control (three paired runs); record thermal status, charge counter delta in µAh if available, OS kills, pressure and cancellation. If unavailable record metric unavailable. Capture dumpsys meminfo and Perfetto scheduling/frequency traces on fixtures. No battery-life projection from a short run. [Memory instrumentation](https://developer.android.com/tools/dumpsys) · [thermal status](https://developer.android.com/games/optimize/adpf/thermal)
4. Proposed shipping gates, **targets, not observations**: text cold validated answer p95 ≤15 s, warm ≤8 s for the fixed test workload, combined peak PSS ≤1.8 GiB, cancellation/visible fallback ≤1 s. No crashes, LMKs or severe thermal state in normal single-turn runs. Stop new inference at SEVERE, power saver or low-memory callback; kill a stuck worker, release resources and show templates. Log measured energy deltas; reject an accelerator if it improves latency at the cost of sustained severe heat or worse energy in the paired workload.
5. Use at least 100 held-out balanced questions (including ambiguous/unsupported, German/English and missing data). Require ≥90% correct supported intent and 100% grounded rendered numerical claims; fallback counts as a miss on a supported prompt. Evaluate ≥100 consented or licensed food crops across lighting/cuisines plus ≥50 mixed/unknown examples. Calibrate thresholds on a separate split. Target ≥80% top-three recall on in-scope dishes, ≤5% confident errors on unknowns, CPU p95 ≤2 s per crop, peak combined PSS ≤600 MiB for vision alone. Publish confusion counts and abstention rate. Label OCR must never silently swap kcal/kJ or portion basis.
6. Revoke URI grants, rotate, background, change OS language, kill worker mid-load/mid-decode, import a truncated file and run on a clean no-Play profile. Recheck after OS, runtime or model changes. Failure disables only the affected adapter/digest. The release fallback chain is validated local model → deterministic topic coaching, or validated classifier → barcode/search/manual recipe. No network retry.

Keep results with the release candidate, including failed runs and the supported digest matrix. An emulator establishes API behavior only. [Test strategy](TEST_STRATEGY.md)
